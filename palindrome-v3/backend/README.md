# Bounded global search and composition, 029

The dev endpoint searches word/role grammar arcs on every request. No completed answer bank is sampled or cached. Input graphs, character indexes and grammar length bounds are compiled once. Seeded randomized traversal chooses actual search paths; a final choice uses distinct normalized tapes. Explicit seeds are reproducible at the normal complete/output-limit budget. Interactive calls use fresh entropy; the frontend excludes its previous result.

Requested lengths are approximate: clamp the target to16–57, then admit only normalized-letter lengths within ±10 and those valid bounds. Eligibility, literal-center and previous-result exclusion tests occur before the unique-output stopping rule. Default target51 produces texts longer than40letters. Limits remain150ms,3000states,24steps and32eligible tapes. Unsupported constraints return409; only explicit fallback=true calls the labeled legacy corpus composer.

There are two small authored grammar families: memo statements and past-task dialogue. Short dialogue has a question and affirmative reply with the same actor. Longer dialogue reopens an intransitive snip/object seam, embeds another licensed question/reply, clarifies 'Pins?' and resolves the original task. It is spoken dialogue with a fragment, not general expository paragraph generation. Actor agreement and object roles are checked. The normalized first component's letters remain around the second; the output is globally checked. It is not plain A+B or repeated A+B+A. The published outer seam is balanced; this does not establish arbitrary noncentral insertion.

Example shape: 'Did Anna snip? Did Bob draw a ward? Bob did. Pins? Anna did.' Its component results and retained seams are exposed in JSON. Lookup/user seeds may supply lexical building blocks, but source reuse and removed modifiers are disclosed. A supported complete task result may be composed as an exact retained component. Legacy Eva/cave seeds supply predicate/object fragments; their entire sentence is not claimed preserved. The geese seed retains its existing31-letter supplied-example expansion when the requested window permits it.

The true center derives from the full normalized output. An original seed center need not stay centered; the geese control shifts e→t. An explicit centre parameter must occupy the actual midpoint. Punctuation and case stay in text, Copy, Read and poster tokens; only exactness/mirror offsets normalize letters.

The grammar is finite and uses palindrome-friendly vocabularies. It has no general-English or world-novelty certificate. Names and several primitive verb/object pairs recur. The known memo fixture is labeled; longer outputs currently concentrate in one dialogue scaffold. Three-level dialogue tested poorly for readability and is not served. No human approval is inferred from owner-model sample ratings.

Installation updates only the existing server/dev_real_search.py, its dev helpers and punctuation shape. server/app.py mount, legacy server/v3.py, bank/models and canonical production frontend remain unchanged. Back up every replaced dev file, compare028 baseline hashes, test before reload, and roll back those files if readiness or the unchanged legacy-output check fails. Use the existing LaunchAgent and preview branch only.

Tests: PYTHONPATH=palindrome-v3 python3 -m unittest backend.test_real_search backend.test_global_search. The suite includes100 independent synthetic grammar/oracle comparisons, held-out recombinations, repeat/window/clamp/exclusion cases, component preservation, punctuation and real centers.
